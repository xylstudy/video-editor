# 2026-09-28｜Editing Skill 评估闭环第一阶段

## 目标

将 Editing Skill 从“Markdown 被注入 Prompt”升级为可审计的运行时能力：能够说明为什么路由、是否注入、Planner 是否声明使用、方案是否满足最小规则，以及该次运行关联到了哪些结果。

## 实现

- 新增 `skills/video-editing/registry.json`，为每个 Skill 定义版本、状态、优先级、适用范围与验证规则。
- 扩展 `SkillRouter`：`SkillPlan` 包含 `decisions`，每项记录 `skill_id`、`skill_version`、`selected_by`、`triggers`、`priority`。
- 在 `VideoScheme` 中分别记录：
  - `selected_skill_refs`：路由选中；
  - `loaded_skill_refs`：实际注入 Planner Prompt；
  - `declared_skill_refs`：Planner/分镜声明使用；
  - `verified_skill_refs`：规则验证通过。
- 新增 `skills/verifier.py`，对方案进行可观察规则检查，并产生 `skill_evaluation.json`；规则验证不宣称 Skill 一定提升成片质量。
- LangGraph 与 Web `run_pipeline_e2e.py` 共用混合路由：Gene 规则结果为必选集合，LLM 根据用户目标、Gene、脱敏素材摘要和 Registry description 仅做补充；LLM 异常时自动降级为确定性结果。
- 路由记录新增 `routing_mode`、`semantic_routing_attempted`、`semantic_routing_error`，并通过 `deterministic_rule / llm_semantic` 区分或合并选择来源。
- Web 确认分镜后会重新验证用户编辑后的方案，并补写 Reviewer、成片和运行报告结果。
- 新增 `skills/analytics.py`，可离线汇总多次运行中的路由、声明、验证率和关联结果。

## 当前边界

- 当前跨任务统计是离线、关联性的；没有自动学习路由权重。
- 当前没有 Candidate → Shadow → Canary → Active 的自动 Skill 晋升机制。
- 当前没有以固定任务集、固定模型与 Prompt 为条件的有/无 Skill 消融实验，因此不能将关联 Reviewer 分数解释为因果收益。
- Web 已接入 `SkillRouter`；无 LLM 的 `editing_transfer` 路径不使用 Planner，因此不注入 Editing Skill。
- 混合路由会额外产生一次小规模 LLM 请求；当前没有 Embedding/RAG，语义层也不会自动利用历史评测学习权重。

## Editing Skill 离线学习闭环 P0

### 新增能力

- 新增 `skills/experience.py`：从 Run 产物自动抽取 Run / Decision Experience，仅保存 Gene、MaterialGene、剪辑动作和评测结果，不保存素材文件；任务级 JSON 与 SQLite 使用稳定 ID 幂等写入。
- `OutputManager` 在 Pipeline Summary、Skill Evaluation 和 Run Evaluation 更新后触发 best-effort 经验刷新；学习链路异常不会拖垮视频生成主任务。
- 新增 `skills/mining.py`：增量处理 pending Experience，对条件/动作进行归一化；未 selected、未 loaded、未 declared、未 verified、无质量结果的数据分别标记拒绝原因；合格记录按决策类型、条件和动作聚合。
- 新增 `skills/candidates.py`：自动生成结构化 Candidate，执行必填 Schema、可验证性、指纹去重、相似重复和同条件动作冲突检查。
- 新增 `skills/experiments.py`：支持版本化固定任务集、同 case 配对 A/B / 消融实验、稳定交叉执行顺序，以及质量提升、胜率、时延、成本门禁。
- 新增 `skills/lifecycle.py`：只有通过候选校验、观察样本门槛和受控实验的 Candidate 才能晋升；晋升时归档旧 Registry/Markdown，支持显式版本回滚。
- 新增保守路由权重学习：使用 Beta 平滑估计，并有限吸收受控实验结果；权重仅影响 LLM 语义候选排序，不覆盖 Gene 确定性路由。
- 新增 `skills/pipeline.py` CLI，覆盖 `ingest / mine / experiment-create / experiment-record / experiment-analyse / promote / rollback / learn-weights / run-all`。
- 新增示例固定任务集、操作 README 和端到端生命周期测试。

### 当前边界更新

- 离线闭环代码已实现，但没有后台定时调度和人工审批 UI，CLI 需要显式执行。
- 已有基础 Skill Markdown 仍由人工整理；新候选从今后的结构化 Experience 中归纳。
- 当前没有真实数百条线上样本与人工标注结论，不能宣称已证明某个 Skill 对真实业务产生因果提升。
- 用户素材的完整到期删除、租户级数据隔离和大规模 Embedding 聚类仍属于生产化工作。
