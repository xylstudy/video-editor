# 2026-09-30｜旅行 Vlog 批量数据与执行链路加固

## 目标

使用有明确授权信息的真实旅行视频构建批量评测集，并针对批跑暴露出的多模态分析、LLM 截断、规划回环、视频素材渲染和成片评测问题加固完整 CLI 链路。

## 数据集与批跑

- 新增 Wikimedia Commons 数据集构建脚本，登记 5 条参考视频和 25 条用户素材的来源、作者、许可、摘要与文件哈希，并组合为 20 个旅行 Vlog 测试案例。
- 新增批量运行脚本，支持从 Web 加密模型配置读取运行参数、按案例顺序执行、失败重试、断点续跑和强制重跑。
- 将“流程完成”和“质量通过”拆成两个状态，避免把生成出 MP4 但评测未通过的案例误报为成功。
- 提交数据集定义、授权说明和聚合报告；原始媒体、逐案例运行结果及 FFmpeg 工作目录保持本地，不进入 Git。
- 将此前误纳入版本控制的 `data/temp` 抽帧、字幕、字体和拼接清单移出 Git 索引；文件仍可在本地按需生成，后续由 `.gitignore` 统一隔离。
- 当前聚合报告记录 13 个已完成案例：9 个通过质量门禁，4 个完成生成但被评测拒绝，0 个子进程失败。剩余案例尚未跑完，不能宣称 20 个案例全部验证完成。

## 多模态分析与 LLM 稳定性

- 参考视频镜头改用按时间顺序抽取的代表帧调用视觉模型，避免依赖部分 OpenAI 兼容接口不支持的内联视频输入。
- 视频素材使用固定数量的均匀采样帧进行语义理解，同时保存采样时间、内容片段、高光区间、可用音频和 Vlog 价值。
- 新增按媒体内容哈希、模型和 Prompt 版本寻址的分析缓存；缓存只保存结构化分析结果，不复制原始媒体和绝对路径。
- LLM 客户端记录不支持 `response_format` 的端点并在进程内复用兼容结论；当服务端以 `finish_reason=length` 截断结果时扩大 token 上限原子重试，拒绝把不完整 JSON 下传给 Agent。
- 为各 Agent 阶段补充请求次数、token、耗时和重试等用量快照，便于运行评测与故障定位。

## Agent 工作流正确性

- 将参考视频分析和首次规划设为必需阶段契约：缺少 Gene 或 `VideoScheme` 时显式失败，由批处理层重试，不再伪装成低质量成功。
- 修正规划回环：Reviewer 要求修改后，Planner 的新方案必须重新经过 Renderer 和 Composer，再审核新的成片，避免最终方案与最终 MP4 不一致。
- 压缩 Re-plan 上下文，只传递当前方案、核心审核问题和必要素材字段，降低长上下文干扰与输出截断概率。
- CLI 完成渲染后增加独立成片评测，并将结果回填 Skill outcome；方案 Reviewer 与最终视频 Reviewer 保持职责分离。
- Reviewer、Planner、Analyst、Material Manager 和 Renderer 日志统一记录阶段用量，运行评测能够汇总真实调用成本。

## 渲染容错

- Remotion 的 Ken Burns 与前景合成组件同时支持图片和视频素材，不再把 MP4 当图片加载。
- 新增确定性的渲染组件解析器；批跑可关闭动态组件生成，未知自定义组件会回退到稳定内置组件。
- FFmpeg 按图片/视频选择不同输入参数，修正无效 `xfade` 转场名，并在转场拼接失败或时长异常时降级为顺序拼接。
- 修正 Windows 中文路径下的 OpenCV 图片读取，并为对应场景补充回归测试。
- 修正镜头检测差值的量纲，将像素差归一化到配置阈值使用的 `[0, 1]` 范围。
